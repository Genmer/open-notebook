# ADR-011: Data export/import — single zip package, id-skip idempotency, direct SQL writes

- **Status**: Accepted
- **Date**: 2026-09

## Context

Open Notebook instances hold everything in one SurrealDB database plus uploaded files under `data/uploads/`. Users moving between machines (or backing up before an experiment) had no way to take notebooks, sources, notes, transformations, source-grouping views/groups, and the associated files and embedding vectors with them. The obvious escape hatches are wrong: SurrealDB dump/snapshot includes tables that must never cross environments (credentials are encrypted with a machine-specific `OPEN_NOTEBOOK_ENCRYPTION_KEY`, `command` rows reference a worker that will not exist on the other side), and it says nothing about uploaded files.

## Decision

**One pair of surreal-commands jobs (`export_data` / `import_data` in `commands/data_transfer_commands.py`) that write/read a single zip package (`format_version` 1), with import idempotency defined as skip-whole-record-by-id.**

- **Package layout**: `manifest.json` (strictly pydantic-validated: version, app version, embedding model id + dominant dimension, per-table counts, per-file sha256/size) + `data/*.ndjson` (one JSON object per line, streamed line-by-line — never whole-file loads) + `files/<source_id_key>/<original_name>`. All DB reads use keyset pagination (`WHERE id > $last ORDER BY id LIMIT n`, RecordID comparison verified on SurrealDB 2.6.5); file IO and hashing run in `asyncio.to_thread` with chunked copies. Export writes a `.tmp` zip and `os.replace`s it, so the download endpoint can never serve a half-written package.
- **Scope**: notebook, source, source_insight, note, transformation, source_view (custom views only — the two default view rows are re-created by `ensure_default_views()` on import), source_group, edges reference/artifact/source_group_member, source_embedding chunks, and files whose `asset.file_path` still exists on disk. **Excluded**: credential, model_usage, command, chat_session, refers_to — none of these tables appears in any export query, so credentials physically cannot enter a package. The `source.command` / `source.embedding_command` worker pointers are not exported (column list) and are left unset on import.
- **Progress carrier**: new SCHEMALESS table `data_transfer_state` (migration 30) with fixed ids `export`/`import`, written best-effort via `repo_upsert` (`{stage, percent, message, error}` + terminal `result`). surreal-commands has no native progress API (verified against the installed package); this mirrors `classify_progress`. The API layer pre-writes a `queued` state before submitting so the UI immediately leaves the previous run's terminal state; the command's own status record stays authoritative for terminal states.
- **Import writes go through direct SQL, never domain `save()`**: `Source._prepare_save_data` strips the embedding progress fields and `Note.save` submits embed jobs — both unacceptable for a restore. Instead each record becomes `CREATE <inline-id> SET field = $bound_param, ...` (the `_rid_sql` inline-id + parameter binding pattern from classification_commands), edges become `RELATE <inline-id>->edge-><inline-id>`, and the only UPDATE in the whole feature rewrites `asset` on sources created by that same import run (new file path after extraction). A field whitelist (TABLE_FIELDS, asset sub-whitelist) mitigates importing through a path that bypasses Pydantic domain validation; CREATE (not UPSERT) means an id collision is a loud bug, never a silent overwrite.
- **Idempotency = skip whole records by id**: precheck loads each table's existing ids (and each edge table's (in, out) pairs) into memory sets once — `repo_query` opens a fresh connection per call, so per-row lookups are not viable. A pre-existing record is skipped together with its file, its embedding chunks and its edges; the second import of the same package writes zero statements (hard acceptance test). Embedding chunks additionally skip when their source was skipped; edges are only created for records this run created (an untouched record's notebook membership stays untouched), after a pair-set dedup against both the DB and package-internal duplicates. There is no DELETE anywhere in the feature.
- **Safety**: import validates everything before the first write — zip member names against a strict whitelist regex (no `extractall`, `..`/backslash/absolute names reject the whole package, unknown `data/` tables rejected), manifest structure and `format_version == 1`, and an uncompressed-size cap (`OPEN_NOTEBOOK_MAX_IMPORT_UNCOMPRESSED_MB`, default 4096) computed from the zip central directory (decompression-bomb guard; the transport layer already caps uploads at 100MB via the existing middleware). File sha256 is verified during the streamed copy; a mismatch deletes the half-written file, warns, and leaves the source with its `asset.url`.
- **Cross-environment vector mismatches warn, never block**: manifest embedding model ≠ current default, dominant dimension ≠ target's dominant dimension (computed client-side with bincount over `array::len` values — `GROUP BY` on an aliased expression collapses in this SurrealDB version), and transformation `model_id` not present in the target all land in `warnings` in the final summary. The DB already tolerates mixed-dimension vectors (classification pools around a dominant dimension), so blocking would be stricter than the rest of the app.
- **API**: `/api/data-transfer/export` (+ `/status`, `/download`, DELETE `/package`) and `/api/data-transfer/import` (multipart zip, + `/status`). Same-kind concurrency is rejected with 400 via the `command` table (`status IN ['new','running']`); export and import may coexist. Uploads stream to `data/imports/<uuid>.zip` (`shutil.copyfileobj` in a thread — the existing `save_uploaded_file` reads the whole body into memory); the package zip is deleted after a terminal outcome (kept for transient-failure retries, which resume safely thanks to id-skip).

## Alternatives considered

- **SurrealDB `surreal export`/snapshot** — rejected: imports credentials that cannot be decrypted elsewhere, worker `command` rows, and chat sessions by design; no file awareness.
- **Per-table JSON dumps via domain models (`Source.save()` etc.)** — rejected: save() paths strip embedding progress and auto-submit embed jobs; exactly the side effects a restore must not have.
- **UPSERT-based import** — rejected: a bug or a concurrent writer would silently overwrite target data; CREATE-on-collision makes the failure visible.
- **Resumable/chunked import** — rejected for v1: id-skip already makes re-running an interrupted import the resume strategy; manifest-level checkpointing can be added later without format changes.
- **Package encryption** — rejected: the zip lives on the user's machine between export and import; transport protection belongs to whoever moves the file. Revisit if packages ever transit through a server.

## Consequences

- `format_version` 1 is frozen: future format changes must bump it and keep `format_version == 1` packages importable (or explicitly rejected with an upgrade path note).
- The worker must be restarted once to register `commands/data_transfer_commands.py`; the API picks it up via `--reload` (a stale worker leaves a submitted export/import command queued forever — same boundary as existing commands).
- Import bypasses domain-model validation by design; the TABLE_FIELDS whitelist plus strict manifest validation are the compensating controls, and any new sensitive table added later must be kept out of the export query set (a test asserts the exclusion).
- `data/exports/` accumulates packages until deleted (UI button or manual cleanup); automatic retention is a future improvement.
